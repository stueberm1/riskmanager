[[section-architecture-constraints]]
== Architecture Constraints

[[programming-conventions]]
===  Conventions

[cols="1,3" options="header"]
|===
| Convention | Motivation/Description
| We are using semantic versioning for modules and apis | link:https://semver.org/[Semantic Versioning] allows client to identify breaking changes and non-breaking changes in programming models by viewing the current version of a module
only. So they can decide to switch to a new version or not as it matches the own project plan.
| On breaking API changes we keep the api before at least for half a year | It is more complicate to maintain two or more
versions of an api in parallel, but it is harder to enforce clients to take all API changes as soon they got released.
We try to avoid breaking changes, but in the beginning they can occur more often, then the system get more experience.
|===
