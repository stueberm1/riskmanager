Motivation::

The Service is build around its core functionality and model.

Presentation and interactions aspects (concerns) are externalized and communicating with the core functionality using
the provided ports only.

Separating dependency injection and system configuration aspects from the core business functionality allows to use the core functionality as a standalone system/service (using the popular spring-framework) as well as in a plugin for several
(Java-based) integrated development environments without modifications of the core.

The standalone service uses the http-api or a suitable web-framework with spring, while the plugin(s) integrates the risk-manager-core together with a suitable persistence provider directly.
